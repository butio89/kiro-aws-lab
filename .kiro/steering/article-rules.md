# 記事の書き方ルール

記事を書く・レビューするときに必ず守るルール。品質と検索評価、そして法令順守（景表法・ステマ規制）を担保するためのもの。

## ファイルの形式

- 記事は `content/posts/<slug>.md` に Markdown で作る。
- `<slug>` は半角英数とハイフンのみ（例: `kiro-serverless-todo`）。URLになる。
- 先頭に必ずフロントマターを書く:

```
---
title: 記事タイトル（32文字前後、キーワードを前方に）
date: YYYY-MM-DD
tags: [Kiro, AWS, サーバーレス]
excerpt: 一覧に出る要約（80〜120文字。読みたくなる一文）
---
```

## 見出しの使い方（ビルダーの制約）

- 本文の見出しは `##`（h2）から始める。`#`（h1）はタイトルとして自動生成されるため本文では使わない。
- 使えるMarkdown記法: `##`〜`####`、`-`/`1.` リスト、`> ` 引用、```` ``` ```` コードブロック、`**太字**`、`*斜体*`、`` `コード` ``、`[表示](URL)`。
- 表は生HTMLの `<table>` ブロックで書く。

## 記事の品質基準

- 一次情報を含める: 実際に動かした結果、出たエラー、所要時間、ハマった点など「体験」を必ず入れる。
- 冒頭で「この記事で何が分かるか / 誰向けか」を明示する。
- コードは動く状態で載せる。コマンドはコピペで実行できる形にする。
- 手順は再現可能に。前提（AWSアカウント、リージョン、バージョン等）を明記する。
- 結論を先に書く（忙しい読者向け）。
- AIが生成しただけの内容をそのまま公開しない。必ず人間が事実確認・加筆する。

## SEO

- 想定検索キーワードを1つ決め、タイトル・冒頭・見出しに自然に入れる。
- タイトルは具体的に（「〇〇の作り方」「〇〇でエラーが出たときの対処」など）。
- 内部リンク: 関連する既存記事があればリンクする。

## アフィリエイト・広告のルール（重要 / 法令順守）

- ステマ規制対応: 広告・PRを含む記事や箇所には必ず「PR」「広告」等を明示する。
- 紹介リンクには `rel="nofollow sponsored noopener"` を付ける。
- 紹介ボックスは以下の生HTMLブロックで書く（Markdown内で空行を入れないこと）:

```
<div class="affiliate-box">
<div class="label">PR</div>
<h4>商品・サービス名</h4>
<p>なぜおすすめかを、読者目線で1〜2文。</p>
<a class="btn" href="ASPで取得したリンク" rel="nofollow sponsored noopener" target="_blank">詳細を見る</a>
</div>
```

- 実際に使っていない・調べていない商品は勧めない。誇大表現（「絶対」「必ず稼げる」等）は使わない。
- 1記事あたりの紹介は多くても2〜3個まで。記事の主目的は課題解決であって販売ではない。
