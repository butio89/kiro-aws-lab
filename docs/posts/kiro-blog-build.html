Kiroで「AIに記事を手伝わせる技術ブログ」をゼロから作ってみた

2026-09-12
Kiroブログ運営静的サイトAI

はじめに

この記事は、AI開発ツール Kiro だけを使って「AIに記事作成を手伝わせる技術ブログ」の基盤をゼロから作った制作記です。対象読者は、Kiroを触り始めたエンジニアや、AIにブログ運営を手伝わせたいと考えている人です。

先に結論を書くと、追加パッケージのインストールなし・Kiroとの対話だけで、記事を書ける状態まで作れました。ここでは全体像、作り方、そして実際に使ってみた感想を順に紹介します。

作ったもの

作ったのは次の2つです。

  • 依存ゼロの静的ブログ：Markdownで記事を書き、Node標準機能だけでHTMLに変換する
  • AI記事作成ワークフロー：Kiroにブログの方針とルールを教え、「テーマ→構成→下書き」を手伝わせる仕組み

ディレクトリ構成はこうなっています。

toybox/
├─ content/posts/        ← 記事の元Markdown（ここに書く）
├─ site/                 ← 公開する静的サイト
│  ├─ index.html         ← 記事一覧（自動生成）
│  ├─ posts/             ← 記事HTML（自動生成）
│  ├─ assets/style.css   ← デザイン
│  └─ scripts/build.mjs  ← Markdown→HTMLビルダー
├─ templates/            ← 構成・下書きの雛形
└─ .kiro/
   ├─ steering/          ← ブログ方針・記事ルール・AI手順
   └─ hooks/             ← 保存時に自動ビルド

なぜKiroで作るのか

Kiroには steering（AIに常時参照させるルール）と hooks（イベントで処理を自動実行する仕組み）があります。この2つのおかげで、単に「コードを書いてもらう」以上のことができます。

  • steeringにブログの方針や記事ルールを書いておくと、AIが毎回それに沿って記事を作ってくれる
  • hooksで定型作業（ビルドなど）を自動化できる

つまり、自分の運営ルールをAIに覚えさせて、それを守らせながら記事を量産できるわけです。

作り方①：静的サイトのビルダー

まずは記事を表示する仕組みです。凝ったフレームワークは使わず、Node標準機能だけでMarkdownをHTMLに変換するビルダーを書きました。狙いは「依存ゼロ」で、環境構築に悩まないことです。

記事の先頭にはフロントマターでメタ情報を書きます。

---
title: 記事タイトル
date: 2026-09-12
tags: [Kiro, AWS]
excerpt: 一覧に表示する要約
---

## 本文はここから

あとはビルドコマンドを叩くだけで、記事一覧ページと各記事ページが生成されます。

node docs/scripts/build.mjs

作り方②：steeringでブログ方針とルールをAIに教える

ここがこの仕組みの核です。.kiro/steering/ に3つのルールファイルを置きました。

ファイル役割
blog-strategy.md誰に何を発信するか（読者像・カテゴリ・収益方針）
article-rules.md記事の品質基準・SEO・アフィリエイトの法令順守ルール
ai-article-workflow.mdAIが記事を作るときの手順（テーマ→構成→下書き）

特に意識したのは、アフィリエイトの法令順守を最初からルールに組み込むことです。PR表記の必須化や、AIが生成しただけの記事をそのまま公開しない（人間が必ず事実確認する）といった点を明文化しました。ここを後回しにすると、規約違反やペナルティのリスクが高くなるためです。

作り方③：hookで保存時に自動ビルド

記事を書くたびに手でビルドコマンドを打つのは面倒です。そこで PostFileSave のhookを作り、content/posts/ のMarkdownを保存したら自動でビルドが走るようにしました。

{
  "trigger": "PostFileSave",
  "matcher": "content[\\/]posts[\\/].*\\.md$",
  "action": { "type": "command", "command": "node docs/scripts/build.mjs" }
}

これで「書いて保存する」だけでサイトが更新されます。

実際に使ってみた

対話しながら進めて、基盤づくりにかかったのは 30分ほどでした。フレームワークの選定や環境構築で悩む時間がなかったぶん、あっという間だった印象です。

一番の気づきは、steeringにルールを書いておくと、AIが本当にそれを守って書いてくれることでした。記事の見出しの付け方やアフィリエイトのPR表記といった細かいルールも、毎回指示し直さなくても自動的に反映されます。運営ルールを一度言語化してしまえば、あとはそれに沿って量産できる感覚がつかめました。

そのほか良かった点は次のとおりです。

  • 構成案を先に出してくれるので、いきなり本文を書くより方向性がぶれない
  • 毎回同じ品質基準で書いてくれるので、記事ごとの当たり外れが少ない

一方で注意が必要だと感じた点もあります。

  • AIの下書きは必ず自分で確認・加筆する必要がある。特に体験談や数値は一次情報なので、AI任せにはできない
  • 生成された内容をそのまま公開すると、事実と違う記述が混ざるリスクがある
